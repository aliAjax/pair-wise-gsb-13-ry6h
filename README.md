# 加油站班次交接 · 补油卡预授权系统

开泵前按卡号、油枪、车牌冻结额度的预授权闭环，含跨班交接、补收结清、版本化调整和重开一致性核对。

## 业务规则

1. **开泵冻结**：按卡号 + 油枪 + 车牌登记，冻结额度必须为正。
2. **同卡唯一**：同一张卡存在未结授权时不得再次开泵；同一油枪同时只能挂一笔未结授权。
3. **拒绝并保留输入**：挂失卡、可用余额不足（卡内余额 − 未结冻结）、车牌不符一律拒绝，页面保留全部输入。
4. **补收后结清**：实际金额超过预授额时，只能先补收差额，补收齐后才能结清并释放冻结；补收不得超额。
5. **跨班交接**：未结授权跨班必须写明处理办法并指定接班班次（可自动新建接班班次），处理完成前不得关班；无未结授权可直接关班。
6. **结清后版本化调整**：结清后冻结额不可改；调整结算金额必须带原因，每次调整另存一个版本，并按差额补扣/退回卡余额。
7. **重开一致**：重新载入后核对卡片、授权、班次、版本四者一致；冲突统一显示 **卡号、油枪、差额、规则、说明**。

## 分层结构（资料 / 判定 / 存储 / 页面分开）

```
src/
├── domain/            # 授权资料层：类型、金额/车牌工具、ID、班次命名（无判定、无存储）
│   └── types.ts       #   FuelCard / Authorization(含版本链) / Shift / Handover / Conflict
├── rules/             # 判定层：纯函数，输入资料 → Result，不读写存储、不碰 Vue
│   ├── openPump.ts    #   开泵冻结判定（挂失/车牌/同卡/油枪/余额）
│   ├── settle.ts      #   超预授补收与结清判定
│   ├── adjust.ts      #   结清后调整 + 快照
│   ├── shifts.ts      #   关班与跨班交接判定
│   ├── consistency.ts #   重开一致性核对（11 条规则）
│   └── accounts.ts    #   可用余额
├── storage/           # 存储层：localStorage 仓储 + 种子数据（不含判定）
├── store/             # 编排层：Pinia，调用 rules 判定、storage 持久化
├── components/        # 冲突横幅、补收/结清、调整组件
└── pages/             # 页面层：开泵预授权、结清台账、班次交接、卡片资料、数据与自检
```

## 使用

```bash
npm install
npm run dev          # 开发
npm run build        # 类型检查 + 构建
npm run test:rules   # 判定层 18 项冒烟测试（纯 Node，无需浏览器）
```

「数据与自检」页可模拟关站重开、注入异常（直接改写底层持久化数据）以演示冲突提示，也可一键恢复演示数据。
